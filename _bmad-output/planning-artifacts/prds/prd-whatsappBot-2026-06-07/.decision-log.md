# Decision Log — Android Voice Expense Recorder PRD

| # | Date | Decision | Rationale | Alternatives Considered |
|---|------|----------|-----------|------------------------|
| 1 | 2026-06-07 | Android widget as primary trigger (not WhatsApp) | User confirmed widget is better UX; no strong reason for WhatsApp in the capture flow | WhatsApp bot trigger |
| 2 | 2026-06-07 | OneDrive (Excel) as storage/review surface | User reviews expenses in OneDrive; existing Azure MSAL auth in Android project aligns with MS Graph API | Google Sheets, local DB, custom app view |
| 3 | 2026-06-07 | Voice input with natural language: "50 taxi", "125 for lunch" | Fastest capture; one tap + one utterance = complete entry | Manual text input, QR scan, photo receipt |
| 4 | 2026-06-07 | Auto-capture date/time at recording moment | Removes a manual step; timestamp is always available from device | Manual date entry |
| 5 | 2026-06-07 | One sheet per month in Expenses.xlsx | User confirmed monthly view; named sheets keep Excel navigable | Single sheet with month column, separate files per month |
| 6 | 2026-06-07 | Raw subject stored as spoken — no category inference | User explicitly declined category mapping; keeps parsing simple | Auto-categorisation with ML/rules |
| 7 | 2026-06-07 | Currency fixed as ILS (₪) | User operates in Israel, single currency | Multi-currency detection |
| 8 | 2026-06-07 | No in-app edit/delete flow | User comfortable editing directly in Excel; keeps v1 scope tight | In-app entry list with edit/delete |
| 9 | 2026-06-07 | No offline queue in v1 | Simplifies architecture; user accepts retry-or-drop on network failure | Local SQLite queue with sync |
